# Publish the TradeDex Trade Portal with Cloudflare Tunnel

This guide exposes the TradeDex web trade portal to users without opening router ports or sharing the machine's IP address.

The local TradeDex pages are:

```text
Admin control panel: http://localhost:8080/
User trade portal:   http://localhost:8080/trade
```

For a public deployment, publish only the trade portal hostname and block the admin routes.

## Choose a Setup

| Setup | Public URL | Recommended use |
| --- | --- | --- |
| Cloudflare Tunnel with a domain | `https://trade.example.com/trade` | Real users and Discord login |
| Quick Tunnel without a domain | Random `trycloudflare.com` URL | Short local testing only |

A stable public site requires a domain added to Cloudflare. A Quick Tunnel changes URL when restarted and is not suitable for a public bot portal with OAuth.

## Requirements

- TradeDex/FusionBot running on the Windows PC that will host the site.
- A Cloudflare account.
- For the recommended setup: a domain active in the same Cloudflare account.
- For Discord login: a Discord Developer Portal application.

## 1. Enable the TradeDex Web Server

In the TradeDex/FusionBot application, open **Web Server Settings** and configure:

```text
EnableWebServer = true
ControlPanelPort = 8080
AllowExternalConnections = false
```

Keep `AllowExternalConnections` disabled when `cloudflared` runs on the same computer as TradeDex. The tunnel connects to `localhost`; the app does not need to accept LAN or Internet connections.

Restart or apply the settings, then test locally on that same PC:

```text
http://localhost:8080/trade
```

Do not continue until the trade portal loads locally.

## 2. Recommended Setup: Tunnel with Your Domain

### 2.1 Add the domain to Cloudflare

1. Open the Cloudflare dashboard and go to **Websites**.
2. Add your domain, for example `example.com`.
3. At the registrar where you purchased the domain, replace its nameservers with the two nameservers assigned by Cloudflare.
4. Wait until the domain status in Cloudflare is **Active**.

If the domain does not appear as a choice when creating a public application route, it is not active in the same Cloudflare account yet.

### 2.2 Create the tunnel

The Cloudflare dashboard wording may change slightly, but the route is currently under:

```text
Zero Trust > Networks > Connectors > Cloudflare Tunnels
```

1. Create a Cloudflare Tunnel and name it, for example `tradedex`.
2. Choose the **Windows** connector installation method.
3. On the PC running TradeDex, open PowerShell as Administrator and execute the installation command generated by Cloudflare.
4. Return to the tunnel page and verify the connector status is **Healthy**.

Important: run `cloudflared` on the same PC as TradeDex if the service URL will be `localhost:8080`. `localhost` always means the machine running the tunnel connector.

### 2.3 Publish the user hostname

Inside the `tradedex` tunnel, open:

```text
Published application routes
```

Do not use **Hostname routes** for this public website. Hostname routes are for private routing/Cloudflare One client scenarios.

Add a published application route:

```text
Subdomain: trade
Domain:    example.com
Path:      leave empty

Service type: HTTP
Service URL:  localhost:8080
```

The public portal will be:

```text
https://trade.example.com/trade
```

Do not put `/trade` into the service URL. Cloudflare should forward the entire site to `http://localhost:8080`; the browser path selects the trade portal.

### 2.4 Fix `Bad Request - Invalid Hostname` if it appears

If the tunnel is Healthy and the browser displays:

```text
Bad Request - Invalid Hostname
HTTP Error 400. The request hostname is invalid.
```

edit the published application route and open its origin/additional settings. Set:

```text
HTTP Host Header: localhost:8080
```

This makes the forwarded request match the local Windows HTTP listener expected by TradeDex.

## 3. Configure Discord Login

Once the public hostname works, set the callback URL in **both** locations below:

```text
https://trade.example.com/api/trade/auth/callback
```

In TradeDex/FusionBot **Web Server Settings**:

```text
DiscordOAuthClientId     = your Discord application client ID
DiscordOAuthClientSecret = your Discord application client secret
DiscordOAuthRedirectUri  = https://trade.example.com/api/trade/auth/callback
```

In the Discord Developer Portal:

```text
Your Application > OAuth2 > Redirects
```

Add the exact same callback URL:

```text
https://trade.example.com/api/trade/auth/callback
```

Do not append `/trade` to the OAuth callback URL.

## 4. Redirect the Hostname Root to the Trade Portal

By default, the local root path `/` is the bot admin control panel, while `/trade` is the user portal. Create a redirect so users who type only the hostname land on the trade page.

In the Cloudflare zone for `example.com`, go to:

```text
Rules > Redirect Rules > Create rule
```

Create a single redirect:

```text
Rule name: Redirect trade root to trade portal
```

Custom filter expression:

```text
(http.host eq "trade.example.com" and http.request.uri.path eq "/")
```

Redirect settings:

```text
Type:        Static redirect
Destination: https://trade.example.com/trade
Status code: 302
```

After testing, `301` may be used for a permanent redirect. `302` is easier while initially configuring the portal because browsers cache it less aggressively.

## 5. Block Admin Panel Routes on the Public Hostname

A redirect is convenience, not access control. Someone could still request admin routes directly unless they are blocked.

In the Cloudflare zone for `example.com`, go to:

```text
Security > WAF > Custom rules > Create rule
```

Create a rule named:

```text
Block non-trade routes on public portal
```

Use the following expression, replacing `trade.example.com` with your hostname:

```text
(http.host eq "trade.example.com" and not (
    http.request.uri.path eq "/"
    or http.request.uri.path eq "/trade"
    or http.request.uri.path eq "/trade/"
    or http.request.uri.path eq "/TradePortal.css"
    or http.request.uri.path eq "/TradePortal.js"
    or http.request.uri.path eq "/icon.ico"
    or http.request.uri.path eq "/sv_mode_image.png"
    or http.request.uri.path eq "/plza_mode_image.png"
    or http.request.uri.path eq "/swsh_mode_image.png"
    or http.request.uri.path eq "/NormalPokeball.svg"
    or http.request.uri.path eq "/Pokeball1SVG.svg"
    or http.request.uri.path eq "/Pokeball2SVG.svg"
    or http.request.uri.path eq "/Pokeball3SVG.svg"
    or http.request.uri.path eq "/Pokeball4SVG.svg"
    or http.request.uri.path eq "/Pokeball5SVG.svg"
    or http.request.uri.path eq "/Pokeball6SVG.svg"
    or http.request.uri.path eq "/Pokeball7SVG.svg"
    or http.request.uri.path eq "/Pokeball8SVG.svg"
    or http.request.uri.path eq "/Pokeball9SVG.svg"
    or starts_with(http.request.uri.path, "/api/trade/")
    or http.request.uri.path eq "/api/bot/localization"
    or http.request.uri.path eq "/api/bot/instances"
))
```

Set the action to:

```text
Block
```

The Trade Portal currently calls `/api/bot/instances` to display the active game mode. It must be allowed for the portal to render its current mode reliably. This route may reveal basic bot instance information. For a hardened deployment, the application should expose a dedicated public mode/status endpoint and the portal should stop requesting `/api/bot/instances`.

The public hostname will no longer be usable for admin work. Use the local control panel instead:

```text
http://localhost:8080/
```

If remote administrator access is required, publish it on a separate hostname protected with Cloudflare Access authentication, never on the user trade hostname.

## 6. Setup Without a Domain: Temporary Quick Tunnel

Use this only for testing. A Quick Tunnel creates a random temporary public URL and does not provide a stable domain for users.

1. Download `cloudflared` on the PC running TradeDex.
2. Confirm the local portal loads:

   ```text
   http://localhost:8080/trade
   ```

3. Open PowerShell in the folder containing `cloudflared.exe` and run:

   ```powershell
   .\cloudflared.exe tunnel --url http://localhost:8080 --http-host-header localhost:8080
   ```

4. `cloudflared` prints a temporary URL similar to:

   ```text
   https://random-words.trycloudflare.com
   ```

5. Open:

   ```text
   https://random-words.trycloudflare.com/trade
   ```

Limitations:

- The URL changes when the tunnel is restarted.
- The admin root path can also be reachable because you do not control WAF/Redirect Rules for the temporary Cloudflare hostname.
- Discord OAuth requires changing the callback URL in TradeDex and Discord whenever the temporary URL changes.

For those reasons, do not use Quick Tunnels to provide the trade portal to real users.

## 7. Keep the Tunnel Online

For a domain-based tunnel installed using Cloudflare's Windows connector command, the connector normally runs as a Windows service.

From an elevated PowerShell prompt:

```powershell
sc.exe query cloudflared
Start-Service cloudflared
Restart-Service cloudflared
```

In the Cloudflare dashboard, the tunnel should show:

```text
Healthy
```

TradeDex itself must also remain open and its web server enabled. If the app stops, the tunnel may remain Healthy but visitors receive a gateway/origin error.

## Troubleshooting

### Cloudflare shows `Bad Gateway`

Cause: the tunnel is online but cannot reach the TradeDex web server.

Checks on the PC running `cloudflared`:

```powershell
Invoke-WebRequest -UseBasicParsing http://localhost:8080/trade
netstat -ano | Select-String ":8080"
```

Verify:

```text
EnableWebServer = true
ControlPanelPort = 8080
Service URL = localhost:8080
Service Type = HTTP
```

Do not configure the origin as `https://localhost:8080` unless you have separately set up HTTPS on the local app.

### Cloudflare shows `Bad Request - Invalid Hostname`

The tunnel reaches TradeDex, but Windows rejects the public Host header. Set this on the route:

```text
HTTP Host Header: localhost:8080
```

### The page loads but images or scripts are missing

The WAF block rule is denying required static assets. Ensure the allow-list includes the Trade Portal JavaScript, CSS, icon, mode images, and Pokeball SVG routes shown in the WAF expression above.

### Discord login fails after moving to the public URL

Verify the same exact URL appears in both TradeDex settings and the Discord Developer Portal:

```text
https://trade.example.com/api/trade/auth/callback
```

### The domain does not appear while adding a published application route

The domain must be added to the same Cloudflare account and show an active status under **Websites** before it can be selected in the tunnel's public route.
